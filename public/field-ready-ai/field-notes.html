The whole session in three facts

It predicts one token at a time — probable is not true, so verify what matters.

It re-reads everything, every time — there is no memory; the transcript is the memory. New task → new chat.

Its desk gets worse the more you pile on — more context is not better context.

What we covered

  • The pipeline. Tokenizer → embeddings → transformer → probabilities → decode, then loop. The model picks one token, re-reads everything, and repeats — a few hundred times per answer.
  • Why it's confident and wrong. It selects the most probable next token, and probable ≠ true. Fluency is not knowledge; confidence is a property of the sampling, not the facts.
  • The desk. The context window is working memory. Attention is a finite budget, and overloading it makes answers worse — context rot is real.
  • The tokenizer. Byte Pair Encoding merges whatever was frequent — so specialist jargon fragments expensively, and non-English scripts pay twice (heavier bytes, fewer merges).
  • The money. Everything — your text, your files, your project instructions, the whole conversation — is re-sent on every message. Long threads grow expensive cumulatively.
  • The harness. The model is the brain; the harness is everything around it — tools, permissions, and how context reaches the desk. Writing project instructions is hand-building a harness.
  • Plans, plainly. Pro is $20/month; usage runs on a rolling 5-hour window plus a weekly cap, from one shared pool. With optional usage credits switched off, $20 is a hard ceiling.
  • Tools and models. Chat is a conversation; Cowork and Code are handoffs. Start on the default model; escalate only when quality actually fails.

Demos you can run yourself

The live tokenizer →
Watch Byte Pair Encoding compress raw bytes into tokens, merge by merge. Try the presets — plain English vs. technical jargon vs. Malayalam vs. JSON — then type a sentence from your own week and see what it costs.
The expensive thread
Ask a trivial question in a fresh chat, then ask the identical question at the bottom of a long working thread with files attached. Same words — roughly a hundred times the cost, because the whole thread is re-read for every token of the reply. The single biggest habit that follows: new task → new chat. quick one — what does p95 mean again?
Bare chat vs. a project
Ask "is this result acceptable?" in an empty chat and you get a hedge. Ask inside a project holding your standing rules and baseline file, and you get a verdict in your mandated format. Same model — different desk.

The habits, ranked

  • New task → new chat — bigger than everything below combined.
  • Stable knowledge lives in a project, written once.
  • Route by difficulty — default model first, escalate on actual failure.
  • Right information, not all information.
  • Extract before you attach.
  • Front-load the brief; don't negotiate over ten rounds.
  • Compact formats — CSV beats pretty-printed anything.

Session 01 · July 11, 2026

Meet the Intern

The kickoff — where the cohort is, where it's going, and the one mental model everything else hangs on. One real workflow, run four ways, in twenty-five minutes.

Meet the Intern — where you are, where we're going (July 11, 2026). Hosted on SharePoint; viewing may require sign-in.

The problem this program answers

Every week brings a new tool, a new model, a new thing you're apparently already behind on. Chasing that firehose is a losing game — so this program inverts it:

Instead of you catching up with AI,
AI catches up with your work.

The room

Everyone in this cohort already uses AI weekly. Between them they've tried five-plus tools, and one has already shipped a working app with AI. So there is no beginner script here — the wall this group has hit isn't using AI, it's making it repeatable: for themselves, and for their teams. When asked where the program should go, the vote was unanimous — agents and automation, rolling AI out to teams, documents and data, evaluating tools.

That's not my curriculum.
That's yours.

The one mental model

Working with AI is managing a brilliant intern — tireless, has read everything, knows nothing about your business until you brief it. And confident even when it's wrong — which is why its work never ships unreviewed.

The good news: if you've ever worked with an intern, you already have the core skill — delegation. Brief well, give context, review the work. This program just points that skill at a new hire. As one of the cohort put it in the room — "consider us as interns." That framing shaped everything that followed, including Session 2 itself.

The ladder

The program's spine — four steps, each trading a little setup for a lot of repeatability:

StepWhat it isWhat changes
1 · PromptYou brief the intern every timeWorks — but you re-explain everything, every time
2 · ProjectA permanent job descriptionInstructions and reference files written once, applied always
3 · SkillThe intern owns the whole SOPThe entire procedure, packaged and callable on demand
4 · AgentThe intern runs it unpromptedWatches the folder, executes the SOP without being asked

The demo: one workflow, three ways

A real performance-engineering workflow — post-test reporting and baseline comparison — run live on synthetic data, up the first three steps of the ladder:

  • Step 1 — the prompt. Baseline and cycle results attached, the full SOP pasted as one long brief. It caught the planted story: a critical +42% regression on the checkout-payment path, a search endpoint breaching its P90 and throughput targets, an error-rate spike — and one transaction that had genuinely improved. Then the limitation, out loud: nobody retypes that paragraph every cycle. So don't.
  • Step 2 — the project. Same rules written once as project instructions. New cycle attached, and the only thing typed was "Here are this cycle's results." It flagged the new regressions — including a +31% slowdown on a revenue path — and noticed something subtler: last cycle's critical issue was back at baseline. The fix, confirmed. That's half of why baselines exist.
  • Step 3 — the skill. The whole SOP — validation rules, thresholds, severity, report format — written in plain English in a skill file. Not code. And not hand-written either: it was built by describing the SOP to Claude in one conversation. Fresh chat, files attached, one sentence — "Process this cycle's results." — and out came a downloadable Excel report you'd attach to a stakeholder email.
One sentence in, a stakeholder-ready file out.
That's the difference between using AI and owning a workflow.

And wherever the AI stumbled along the way, that was part of the lesson, not a blooper: trust, but verify. The engineer stays in the loop — that's a feature of the ladder, not a bug.

How the program runs

  • Saturdays, live — working sessions on the cohort's actual workflows, not lectures.
  • Field Notes within 48 hours — recording, notes, and every prompt shown, so nobody takes notes in the room.
  • Light homework — designed to surface material for the next session.
  • 1:1s between sessions — a small cohort means real bandwidth.

Decisions made together

  • Fundamentals first — the cohort asked, Session 2 delivered.
  • Personal subscriptions set up together, after the fundamentals, with cost protections on from day one.
  • A shared channel as the home for notes, questions, and resources.
  • After fundamentals: building an app together, to see the full thought process of building with AI.
  • Standing recording rule: no company or client names.

Homework

The Delegation Diary: through the week, any moment you catch yourself thinking "an intern could have done the first 80% of this" — write it down. Two minutes a day. Those entries are the raw material the ladder gets climbed with.
